### ③ α 数值互相打架（2026-08-23 已定案：全部不可跨运行比较）

| 来源 | α 说法 |
|------|--------|
| `problem_and_solutions.md` §2.2(A) | mean=**0.656**（高 α，信任 KG；旧 smoke 日志） |
| `fix_plan_kg_quality.md` 根因2 | α 卡在 [0.018, 0.17]，mean=**0.117**（b=-2.0 低端饱和，修复前） |
| `statistics.md` §二（旧表，**已撤回**） | HotpotQA 0.292 / 2Wiki 0.804 / MuSiQue 0.855 |
| **`statistics.md` §二（2026-08-23 单一状态重测）** | HotpotQA **0.918** / 2Wiki **0.914** / MuSiQue **0.908** |

**最终真相**: 以 2026-08-23 重测为准。关键更正是**这四个说法互相打架的原因**已经查清——它们不是"修复前后的历史快照"，而是**四次不同代码/缓存状态下的运行，彼此不可跨运行比较**：

1. `f_confidence` 在 `EntityLinker` 缓存为空时恒等于 0（`entity_linker.py` 的 `if not cache_items: return 0.0`），而 `indexes/entity_cache.jsonl` 是不入版本库的运行时状态，会在评测过程中自行增长。冷缓存运行与热缓存运行不是同一个函数。
2. D1（commit `e6b2198`）把推理期硬编码的 `f_entropy = 1.0` 换成真实 token logprob。因 $W_2<0$，这一项单独就把 α-logit 抬高 $+0.19$–$+0.26$。
3. `--alpha_bias_correction` 在不同运行里取 0 或 +0.78，单独造成 α 0.761 vs 0.921 的差别。

**可判定性**：残差 $W_1\cdot conf + W_2\cdot ent$ 在 $conf,ent\in[0,1]$ 时必落在 $[W_2, W_1]=[-0.583,+1.709]$。旧表的 HotpotQA α=0.292 在实测 density 0.924 下需要残差 $-0.647$，**低于下界**，因此它不可能是在 +0.78 校正下产生的——与 `03_method.md` §3.4 声称的"已施加 +0.78"直接矛盾。同一数据集同一 seed 的四次归档运行给出 0.125 / 0.441 / 0.493 / 0.918，**同数据集内的状态漂移（0.79）远大于旧表声称的跨数据集效应（0.563）**。

**引用规则**：只引用 2026-08-23 三臂重测（每数据集 n=300、同一冻结缓存快照、同一 bias）。前四个数值一个都不能引用，包括旧 §二。

### ⑥ α-gate 的宣称 vs 实际行为

- 宣称（`paper_design_new.md` §2.2、`problem_and_solutions.md` §一）：α 每步"动态选择信任 KG/文本"、"密度高置信高→强制 KG"。
- 实际（`fix_plan_kg_quality.md` 根因1/6 + 记忆 [[alpha-gate-eval-noop]]）：推理时 f_entropy 恒 1.0、同题所有步 α 相同；**eval 阶段 α 只作 telemetry，不参与 KG 门控**。

**最终真相**: α 只在**训练期**对 reward 做 KG/文本重加权；**eval 阶段不门控 KG**（不能靠 α 抬 EM/F1）。论文把 α 描述成"运行时动态门控"是过度宣称，需按实际行为改措辞。
