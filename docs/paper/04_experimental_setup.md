## 4. Experimental Setup

### 4.1 Datasets and Evaluation | 数据集与评估

We evaluate KG-ProWeight on three multi-hop QA benchmarks: **HotpotQA** ($7,405$ dev questions, predominantly bridge and comparison questions), **2WikiMultiHopQA** ($12,576$ dev questions, entity-centric, requiring up to $4$ hops of cross-Wikipedia-document reasoning), and **MuSiQue** ($2,417$ dev questions, compositional multi-hop questions with up to $4$ reasoning hops). All three benchmarks are evaluated under the **full Wikipedia retrieval** setting: the system must retrieve relevant evidence from $\approx 21$M documents rather than the standard distractor setting ($\approx 10$ pre-provided candidates per question). We report Exact Match (EM) and F1 score. Unless otherwise noted, results are on the first $300$ dev questions; we also report primary results on 2WikiMultiHopQA at $n=1000$ for tighter statistical significance. All evaluations use deterministic generation (temperature $=0$). / 评估 HotpotQA（$7,405$ 题）、2WikiMultiHopQA（$12,576$ 题）和 MuSiQue（$2,417$ 题），全量 Wikipedia 检索（$\approx 21$M 文档），报告 EM/F1。

**Statistical protocol.** Every KG comparison in this paper is between two runs over the *same* question set, so we test it as a paired comparison rather than with an independent two-proportion test, which discards the pairing and is markedly less sensitive. For EM (binary per question) we use the **exact-binomial McNemar test**, which conditions on the questions where the two arms disagree; for F1 and IHR (continuous) we use a **paired bootstrap** ($10{,}000$ resamples, seed $42$) for the $95\%$ CI together with a **Wilcoxon signed-rank** test. Pairing is by question id, and questions present in only one arm are dropped and counted rather than silently intersected. Decoding is greedy ($T=0$) with a fixed question prefix, so re-running a checkpoint on the same data is bit-identical and multiple seeds add no information; the residual uncertainty is *sampling* error over the question set, which is why we report CIs rather than seed variance. At $n=300$ and EM $\approx 0.34$ the binomial standard error is $2.7$pp, giving a $95\%$ CI half-width of $\approx 5.3$pp. We do not describe any difference as an improvement unless $p<0.05$. All test outputs are in `outputs/paired_stats/`; the script is `scripts/analysis/paired_stats.py`. / **统计口径**：本文所有 KG 对比都是同一题集上的两次运行，故一律做**逐题配对**检验而非独立二项检验（后者丢掉配对信息，灵敏度低得多）。EM 为逐题二值，用**精确二项 McNemar**（只看两臂判断不一致的题）；F1 与 IHR 为连续值，用**配对 bootstrap**（$10{,}000$ 次重采样，seed $42$）给 $95\%$ CI，并配 **Wilcoxon 符号秩**检验。按 question id 配对，只在一侧出现的题**丢弃并计数**，不静默取交集。解码为贪心（$T=0$）且题目前缀固定，同一 checkpoint 重跑逐位相同，多 seed 不提供额外信息；真正的不确定性来自题集**抽样**误差，故报 CI 而非 seed 方差。$n=300$、EM $\approx 0.34$ 时二项标准误 $2.7$pp，$95\%$ CI 半宽 $\approx 5.3$pp。**除 $p<0.05$ 外，本文不使用"提升/改善"等表述。** 检验输出见 `outputs/paired_stats/`，脚本为 `scripts/analysis/paired_stats.py`。

### 4.2 Models and Baselines | 模型与基线

All model variants build on the Llama-3-8B-Instruct base model [3] fine-tuned via LoRA ($r=32, \alpha=64$, target modules: `[q,k,v,o]_proj`). We compare three conditions: / 所有模型基于 Llama-3-8B-Instruct [3] + LoRA：

- **SFT only** (text-only SFT baseline): student model fine-tuned on Phase-1 teacher trajectories, no KG augmentation. The prompt contains no KG. This baseline establishes the performance ceiling for text-only retrieval. / **SFT only**：纯文本 SFT 基线，提示不含 KG。
- **SFT + KG** (SFT with KG): same SFT student model as above, but the input is augmented with filtered KG triples at inference (§3.4). This condition quantifies the marginal contribution of KG to SFT. / **SFT + KG**：推理时以过滤 KG 增强输入，量化 KG 对 SFT 的边际贡献。
- **PPO + KG** (RL with KG): student model after Phase-3 PPO training (§3.3). Input format at inference is identical to SFT+KG. / **PPO + KG**：阶段三 PPO 训练后的学生模型。

We additionally report PPO without KG ($\alpha \equiv 0$ ablation) on a restricted subset. / 另报告 PPO noKG（$\alpha \equiv 0$）消融。

### 4.3 Implementation Details | 实现细节

**Retrieval**: Hybrid of dense E5-base [40] ($768$-dim vectors over $21$M documents, $32.3$ GB fp16 memory-mapped, chunked search with $2$M rows per chunk) and BM25 (bm25s backend). $60$-way RRF fusion yields top-$50$ candidates, reranked by bge-reranker-v2-m3 cross-encoder [41] to $10$, packed by token budget ($3860$ tokens, $1200$ chars per passage) to fit the model's context window. Generation via HuggingFace pipelines integrated in FlashRAG [39] (max input $6144$, max new tokens $512$, greedy decoding). / 检索：E5-base [40] + BM25 混合，RRF 60 路 → Top-50，bge-reranker-v2-m3 [41] 重排至 10，token 打包 $3860$。

**KG Construction**: Offline entity cache ($35K+$ labels → QIDs), on-disk SPARQL result cache ($64K+$ entries), with online Wikidata SPARQL POST queries only on cache miss (retries $3$, timeout $30$s). Full pipeline operates in offline mode when Wikidata is unreachable. Measured coverage on the built question-KG index: 2WikiMultiHopQA $12{,}576$ / HotpotQA $7{,}405$ / MuSiQue $2{,}412$ entries, mean $15.87$ triples per question (median $15$); $4.9\%$ of questions receive an empty KG overall, rising to $12.4\%$ on MuSiQue, which caps the attainable KG contribution on that dataset. / KG 构建：离线实体缓存（$35K+$）+ SPARQL 结果缓存（$64K+$），离线模式运行。索引实测覆盖：2Wiki $12{,}576$ / HotpotQA $7{,}405$ / MuSiQue $2{,}412$ 条，均值 $15.87$ 三元组/题（中位 $15$）；整体 $4.9\%$ 题目为空 KG，MuSiQue 达 $12.4\%$，这直接限制了该数据集上 KG 贡献的上限。

**Compute**: All experiments on one NVIDIA GeForce RTX 4090 (24 GB). Phase 1+2 complete in $\approx 3$ hours end-to-end; Phase 3 PPO training completes in $\approx 4$ hours ($750$ updates, $\approx 18$s each). Inference throughput $\approx 20$ min per $300$ questions ($\approx 4$s/question). / 计算：一台 NVIDIA GeForce RTX 4090（24 GB），Phase 1+2 $\approx 3$h，Phase 3 $\approx 4$h，推理 $\approx 20$min/$300$ 题。
