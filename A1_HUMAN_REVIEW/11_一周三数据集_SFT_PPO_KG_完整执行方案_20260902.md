# 一周三数据集 SFT / PPO / KG 完整执行方案

> 版本：2026-09-02 v1（计划，不是实验结果）  
> 时间预算：7 天；目标是形成可审计的三数据集闭环，不承诺制造正结果。  
> 当前起点：强 SFT 标准 EM=`.383/.427/.247`；2Wiki SFT+ProofKG EM/F1=`.640/.694`；
> canonical 四臂已确认 PPO-smoke600 在 ProofKG 下仍比强 SFT 低 3pp。

## 1. 一周后的明确目标

### 1.1 必须交付（不以指标正负为条件）

1. HotpotQA、2WikiMultiHopQA、MuSiQue 三个数据集统一使用一种
   **Question-conditioned Passage Evidence Graph（QPEG-v1）** 表示。
2. QPEG 只读取问题和已经检索到的 top-10 passages；不读取 dev/test gold answer、support、
   decomposition，不增加外部知识源。它是对 baseline 已有 passages 的结构化变换。
3. 冻结一个约 4,800 条、三数据集均衡的 continued-SFT 数据版本，并保留来源/哈希/过滤报告。
4. 训练并比较：强 SFT、QPEG-SFT、PPO-O（仅 outcome）、PPO-K（outcome+KG process）。
5. 在相同 n=300/seed42/greedy/canonical scorer 下报告三数据集 EM/F1；在相同 n=100 下统一报告
   IHR；所有失败结果保留。
6. 用配对实验分别回答：KG 供给是否有效、SFT 是否学会利用图、PPO 是否增加收益、KG process
   reward 是否优于普通 PPO。

### 1.2 工程成功目标

| 方面 | 一周目标 |
|---|---|
| 数据多样性 | SFT 约4,800条，Hotpot/2Wiki/MuSiQue各约1,600条 |
| 自动图覆盖 | 三数据集 nonempty≥0.80；每条边 passage provenance=1.0 |
| 图安全性 | dev/test `gold_access=false`；identity/hash join=1.0；每题≤12边 |
| SFT | 标准 legacy replay 不退化超过1pp；QPEG臂 macro EM/F1不低于强SFT |
| PPO探索 | train-only hard cohort oracle@4−greedy≥8pp，valid≥0.90 |
| PPO奖励 | process pairwise≥0.65，process top1≥greedy，才允许PPO-K |
| 最终方向 | PPO-K相对QPEG-SFT macro EM≥+1pp，且相对PPO-O≥+0.5pp |
| 幻觉 | PPO-K相对QPEG-SFT或PPO-O的macro IHR下降≥3个绝对百分点 |

这些是预注册的工程/晋级目标。n=300下约1pp通常不足以构成统计显著结论；论文确认仍以配对
bootstrap CI、McNemar和多seed为准，不把“过工程门”写成“显著优于”。

## 2. 核心战略：主表同资源，ProofKG 作为额外资源增强

### 2.1 同资源主线

`question + frozen top-10 passages → QPEG-v1 → SFT/PPO`

QPEG 不查询 Wikidata。知识内容全部来自 baseline 已经看到的 passages，因此 HotpotQA、2Wiki、
MuSiQue 可以采用统一方法，并能与原标准检索主表放在同一知识资源边界下。需要披露额外的图构建
计算，但不需要重跑完全不消费 KG 的外部 baseline。

### 2.2 额外资源增强线

2Wiki 的 automatic ProofKG（历史 Wikidata）继续单列：SFT EM/F1=`.640/.694`，matched
legacy→ProofKG `+23.7pp`。它证明外部结构化证据的上限，但不与同资源 QPEG 主表混称。

### 2.3 QPEG-v1 的最小实现

每条边统一为：

```text
(head_surface, relation_surface, tail_surface,
 passage_id, sentence_index, sentence_sha256, extractor_version)
```

构建顺序固定：

1. 从问题、passage title 和句子提取实体/日期/数值 mentions；
2. 用 passage title 作为稳定 subject，抽取同句中的谓词短语和 object mention/value；
3. 用跨 passage 的同名实体建立 bridge adjacency，但不创造新事实边；
4. 按问题 relation token overlap、question-anchor 命中、bridge connectivity 排序；
5. 去重后保留 top-12；每条注入边必须能回指原句，否则丢弃；
6. 图为空时显式回退 no-graph，不混入 Wikidata legacy 边。

本周不训练新的图生成大模型，不做开放式 LLM relation invention。允许一次基于 pilot 错误类型的
**通用规则修正**，禁止逐题补丁或读取答案后写边。

## 3. 数据方案：约 4.8k，不重跑全量 Teacher

### 3.1 SFT 数据组成

| 数据集 | 新 QPEG-grounded 轨迹 | 原始接受银标 replay | 合计 |
|---|---:|---:|---:|
| HotpotQA | 800 | 800 | 1,600 |
| 2Wiki | 800 | 800 | 1,600 |
| MuSiQue | 800 | 800 | 1,600 |
| 合计 | 2,400 | 2,400 | 4,800 |

- 原 silver 文件全部只读；replay 从已有 accepted trajectories 派生新版本。
- 新轨迹不调用外部 Teacher：用当前强 SFT 在 QPEG prompt 上 greedy 生成；失败题最多补一次 K=2
  sampling。只接受 Final Answer EM=1、格式合法、引用全部属于可见 QPEG 的轨迹。
- Gold answer 只用于 train split 的接受/拒绝和 PPO outcome reward；不参与图构建。
- 若某数据集无法得到至少600条合格新轨迹，该数据集不得用复制样本凑到800；报告实际规模并触发
  数据门失败。
- train/dev/confirmation 按 qid 和 question family 隔离；已消费评估 qid 不进入训练。

### 3.2 为什么不直接复用 light20

light20 是4,000 Hotpot replay+1,000 gold-derived 2Wiki Proof，缺 MuSiQue，且所有 checkpoint
均未同时通过 replay EM 和 hidden EM 门。本方案改为三数据集均衡、passage-only 自动图、低学习率
短 continued-SFT；旧失败数据与 checkpoint 保留，但不作为新实验起点。

## 4. 实验矩阵：每个结论只由一个对照回答

### 4.1 最小六臂

| Arm | checkpoint | 推理输入 | 回答的问题 |
|---|---|---|---|
| A | 强 SFT | frozen passages，no-QPEG | 原始能力 |
| B | 强 SFT | 同 passages + QPEG | 零训练 KG/图供给效用 |
| C | QPEG-SFT | 同 passages + QPEG | SFT 学习增益 `C-B` |
| D | QPEG-SFT | 同 passages，no-QPEG | C 的 KG 依赖消融 |
| E | PPO-O | 同 passages + QPEG | 普通 outcome PPO 增益 `E-C` |
| F | PPO-K | 同 passages + QPEG | KG process reward 净增益 `F-E` |

补一个成本较低的 F-noQPEG 诊断臂，用于判断 PPO-K 是否只在图存在时工作。外部 baseline 表使用
既有标准结果，并新增最终 F；QPEG 是方法组件，不覆盖 legacy 结果。

### 4.2 必须报告的差值

- `Supply@SFT = B-A`
- `SFT-learning = C-B`
- `Supply@QPEG-SFT = C-D`
- `Outcome-PPO = E-C`
- `KG-reward-PPO = F-E`
- `Total method = F-A`
- 每项均报告三数据集、macro、paired CI、EM gained/lost/tied；IHR 使用统一 judge/qid/template。

## 5. 训练配置

### 5.1 QPEG continued-SFT

- 起点：`checkpoints/sft_legacy_repaired_v2_quota70_hard_seed42_no_text_head/final`
- 数据：上述4,800条，三数据集1:1:1；QPEG-grounded/replay=1:1。
- LoRA保持 r=32/alpha=64/dropout=.05；bf16；max length=6144。
- `lr=2e-6`，effective batch=32，最多120 optimizer updates；保存 step40/80/120。
- 选择最早通过门的 checkpoint，不用最终测试集挑点：
  - 历史 replay n=200：parse≥.995、EM≥.780、hidden EM≥.545；
  - 三数据集 QPEG dev100 macro EM/F1均不低于强SFT，且任一数据集EM退化≤1pp；
  - 无 checkpoint 通过则保留原强SFT，SFT实验记为FAIL，不从失败SFT启动PPO。

### 5.2 PPO-O / PPO-K 配对

- 起点：通过门的 QPEG-SFT；若无SFT通过，则统一从原强SFT启动并明确标记。
- train-only hard cohort：QPEG nonempty、有完整provenance、greedy错误或低置信、K=4有mixed outcome。
- 每轮1,200 trajectories=`300 prompts × K4`；两轮使用相同 qid schedule、seed、更新预算。
- 共同参数：lr=`5e-7`、batch=4、ppo_epochs=1、显式冻结SFT reference、KL coef=.25、target
  KL=8、10% replay、动态2/3-step validity、max_new_tokens=384。
- PPO-O：`4*EM + 0.4*F1`，保留相同invalid penalty，不加process分。
- PPO-K：只增加归一化 process-v2.1，初始权重`.2`；process贡献的P95不得超过正确答案 outcome
  bonus的25%。这是待批准的核心Reward新版本，必须另建配置/Experiment ID。
- 启动前零更新门：valid≥.90、oracle@4−greedy≥8pp、pairwise≥.65、process-top1≥greedy。
  任一失败则不跑PPO-K，不通过继续手调同一确认集过门。

## 8. 一周结束时的结论分支

### A. 理想闭环

QPEG在≥2个数据集有正供给效用，QPEG-SFT不退化，PPO-K>QPEG-SFT且>PPO-O，IHR下降。
可讲：统一passage graph提供跨数据集结构证据，SFT学会使用，KG过程奖励在相同PPO预算下提供
额外收益；2Wiki ProofKG展示额外结构知识的上限。

### B. KG有效、PPO无效

QPEG A/B正向，但F≤C或F≤E。可讲供给与训练解耦：结构化证据有效，当前PPO/reward没有超过
监督学习；不能称PPO有效。

### C. SFT有效、process reward无效

C>B但F≤E。可讲跨数据集graph-grounded SFT有效，同时给出严格PPO-O/K负对照。

### D. QPEG本身失败

Hotpot/MuSiQue confirmation不增益或有害。立即停止4.8k构建/训练；保留2Wiki ProofKG主结果和
跨数据集失败边界。不得为“讲故事”降低门、换qid或事后挑数据集。

## 9. 本周明确不做

- 不构建15k–20k全量数据；不重新调用DeepSeek Teacher生成全量银标；
- 不继续扩长已经失败的同配置ProofKG PPO-smoke600；
- 不把Hotpot/MuSiQue的Wikidata-only失败改判成功；
- 不覆盖legacy索引、baseline、Gold或旧checkpoint；
- 不在同一轮同时改变数据、reward、KL后把收益归给单一组件；
- 不把2Wiki额外Wikidata `.640` 与同资源外部baseline当成严格公平的单变量比较。

## 10. 启动前需要研究者一次性批准的三项

1. 新增版本化 QPEG evaluation protocol（不覆盖legacy）；
2. 启动一次约120 updates的continued-SFT和两次各1200 trajectories的PPO大训练；
3. PPO-K接入归一化process-v2.1且权重`.2`，PPO-O保持0，作为唯一reward变量。

批准后仍按每日门执行：门失败即停止后续昂贵步骤，而不是自动把一周预算全部跑完。
